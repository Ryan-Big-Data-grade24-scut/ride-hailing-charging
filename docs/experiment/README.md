## 1. 数据集

### 1.1 来源

**NYC Taxi & Limousine Commission (TLC), Trip Record Data, yellow taxi, 2024-01**
<https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page>

下载：`https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_2024-01.parquet`（47.6 MB）

### 1.2 清洗

| 步骤 | 规则 | 作用 |
|---|---|---|
| 1 | 丢弃关键字段为空的行 | 官方数据约 4.7% 全空 |
| 2 | `0.3 < trip_distance < 200` mile | 去 0 与量纲错误 |
| 3 | `0 < total_amount < 500` USD | 去退款/异常 |
| 4 | `60 s < duration < 3 h` | 去 driver-side 录入错误与时间戳错乱 |
| 5 | `passenger_count > 0` | — |
| 6 | 保留行程数 ≥ 中位数 75% 的日历日 | 避免残缺日污染 96 格画像 |

**结果：2,964,624 → 2,803,713 笔（保留 94.6%）。**

再剔除行程数不足中位数 75% 的不完整日，**保留下来的 30 个完整工作日共 2,739,936 笔**，96 格画像全部由这 30 天池化估计（`data/profile.json` 的 `n_trips_clean` = 2,739,936）。

> ⚠️ **两个数字别混**：2,803,713 是**清洗后**总量；2,739,936 是**最终进入画像**的量。论文里必须写清后者。

### 1.3 派生出的 96 格画像

每个 15 分钟格 $t \in \lbrace 0,\dots,95\rbrace $：

| 量 | 定义 |
|---|---|
| $\lambda_t$ | 平均订单到达率（全市） |
| $\bar{f}_t$ | 平均车费 |
| $\bar{e}_t$ | 平均每单能耗 $= \bar{d}_t \times \text{kWh/km}$ |
| $\bar{d}_t$ | 平均行程距离 |

**关键设计**：能耗与车费**不直接存储**，而是由距离与单位参数推导。这样敏感性分析改参数时能真正生效。

> ⚠️ 第一版把 `kwh_km` / `fare_scale` 传进 `Env` 但没读，导致峰谷价差 0→2× 结果完全一样。**参数必须真的接进模型。**

### 1.4 从全市到单司机

$$\lambda_t^{\text{driver}} = \frac{\lambda_t^{\text{city}}}{N_{\text{fleet}}}, \qquad N_{\text{fleet}} = \frac{\max_t \lambda_t^{\text{city}}}{\textsf{CAP} \times u_{\text{peak}}} = \frac{1684}{1.01 \times 0.85} \approx 1{,}970$$

$u_{\text{peak}} = 85\%$ 为**假设的晚高峰载客率**（Assumption，扫描范围 40%–100%）。

## 3. 对比实验（已完成 ✅）

**协议**：每种策略在 **600 个独立随机工作日**上蒙特卡洛评估，随机种子 20261001，所有策略共用同一批随机流。

| 策略 | 净收入 | 可行率 | 说明 |
|---|---|---|---|
| **MDP** | **\$946.46** | **95%** | 本方法 |
| 期望值 DP | \$934.15 | 85% | 事后知道需求 |
| 基线：阈值 SOC<40% | \$924.98 | 100% | **最强规则法** |
| 基线：阈值 SOC<30% | \$922.46 | 100% | |
| 基线：阈值 SOC<50% | \$920.66 | 100% | |
| 基线：SOC<40% 就**充满** | \$911.06 | 100% | 同一触发点，但充到 100% |
| 基线：**按最便宜电价充** | \$788.21 | **11%** | **照电价表走的自然策略** |
| 基线：永远不充电 | \$600.09 | **0%** | |

> 输出：`results/policy_comparison.csv`

### 3.1 三个可直接进论文的发现

**发现 1 —— 照电价表走会被自己的策略困死。**
按最低电价充电只充谷段 1 格（约 13.8 kWh），而全天需 54.5 kWh，其余无处可来。**它不是"赚得少"，是"开不出车"**：89% 的日子跑不完。相对 MDP +\$158.25（+20.1%）。

**发现 2 —— 期望值 DP 账面更高但不可用。**
见 `docs/framework/README.md` §4.6。

**发现 3 —— 最优解不在谷段。**
在 570 个可行工作日中，**MDP 策略有 76.3% 的日子会在最便宜电价窗口之外充电**（第二格典型落在 11:15–12:30 或 20:30–22:30）；只有 28.9% 的日子完全待在谷段。但**每一个日子都会选深夜那一格**——04:45 占 87.2%、04:30 占 12.8%，合计 **100%**。

原因：谷段虽然电便宜，但**司机在谷段本来也接不到什么单**——挪到更晚的平段充，多跑几小时赚的钱**超过那 \$0.08/kWh 的价差**。

> 正确判据不是"电价最低"，而是**"电价 + 这一格少赚的车费"最低**。

> ⚠️ **口径更正**：早期版本只报"最好的一天"的充电时刻（04:45 / 11:15 / 20:30），而那是 200 次模拟里的**最优解**，不能当统计量用。现在的数字来自 **600 个工作日的分布**（`code/src/policy_stats.py` → `results/charge_slot_stats.csv`、`results/charge_day_stats.csv`）。方向一致，但结论从"某一天这样充"升级成"**76.3% 的日子这样充**"。

## 4. 消融与扩展实验（已完成 ✅）

### 4.1 消融 A1–A6

消融的目的是回答：**模型里哪个结构是必要的？拿掉会怎样？**

基准行（MDP）：净收入 \$946.46，可行率 95%，充电时刻 04:45 / 11:15 / 20:30。

| # | 消融项 | 已观察 | 结论 |
|---|---|---|---|
| **A1** | **去掉随机性（期望值 DP 替代 MDP）** | 净收入 \$934.15，可行率 95% → **85%**，充电时刻移到 06:30 / 09:15 / 20:00 | 期望值策略在随机需求下**不可用** |
| **A2** | **去掉 TOU 价差（平价电价）** | 净收入 \$947.01，增益 +\$158.25 → **+\$158.80**，充电时刻**完全不变** | **价差不是驱动因素** |
| **A3** | 去掉 CC–CV 衰减（恒功率充电） | 净收入 \$946.46，充电时刻**完全不变** | 本算例下 taper **不影响最优策略** |
| **A4** | 去掉司机时间上限（CAP → ∞） | 净收入 **\$1,239.90**，充电时刻增至 4 格（04:30 / 09:30 / 18:15 / 22:45），单司机服务订单 34.6 → **46.3** | 时间上限确实是**问题的支点** |
| **A5** | reserve 硬约束改成 clamp | clamp 模型自认为 \$987.55，但要从 40 kWh 电池取 **44.5 kWh**；用正确物理一测，同一策略只 \$600.09、可行率 **0%** | **约束类型选错 → 定性错误的解** |
| **A6** | 拉平日内需求形状 | 净收入 **\$1,009.28**，充电时刻 02:30 / 07:45 / 08:45，**三格全落在谷段**；单日订单 34.6 → **46.3** | 机会成本一旦变成常数，**决策权交回给电价** |

> 输出：`results/ablations.csv`、`results/ablations_summary.json`

**A2 是本项目最有价值的消融**：它证明了**峰谷价差不是本问题的驱动因素，机会成本才是**。这条负面结果直接支撑了"网约车补能不能照搬 fleet-level 错峰充电结论"的论点。

**A5 是一个反例式消融**：clamp 版的模型**账面最优 \$987.55，比 MDP 还高**，看上去赢了——但它必须从 40 kWh 的电池里取出 44.5 kWh（111%）。用正确物理复核，同一套策略只值 \$600.09、可行率 0%。价值在于展示"约束类型选错会得到定性错误的解"，建议在论文中单独成小节。

**A6 与 A2 互为镜像**：A2 拿掉的是**价格**的形状，A6 拿掉的是**机会成本**的形状。A2 里决策权留在机会成本手上（时刻照旧）；A6 里决策权交回电价手上（时刻全部落回谷段）。两条一起说明：**决定充电时刻的是这两条曲线哪一条更陡**。

**A4 说明时间上限是模型的支点**：拿掉 CAP 后净收入从 \$946 跳到 \$1,240，充电时刻从 3 格变成 4 格并散到 09:30 / 18:15——因为需求不再饱和，机会成本失去了日内形状，"何时充电"就退化成单纯挑便宜时段。

### 4.2 v2 扩展：循环多日 MDP、最优起始 SOC 与跨日影子价格 ⭐

单日模型有一个隐含的免费午餐：**每天从 80% 满电出发**。真实司机不是这样——他带着**昨天剩的电**上班。因此把单日模型改成**跨日循环**：一天结束时的状态通过跨日价值函数 $W$ 接到第二天的起始状态，求 $W(s) = V(0,s)$ 的不动点，再从 $W$ 导出跨日储能的影子价格 $\mu = dW/ds$（详见 `docs/framework/README.md` §4.7）。

| 量 | 结果 |
|---|---|
| 循环值迭代 | **34 轮收敛**，中心化残差 9.29e−10 |
| 跨日储能影子价格 $\mu$ | **\$0.2414/kWh** |
| $\mu$ 的独立交叉验证（20 天有限时域 DP） | **\$0.2414/kWh**（一致到 9 位有效数字） |
| TOU 价格区间 | \$0.11（谷）– \$0.42（峰） |
| **最优起始 SOC** | **36.8%**（不是 100%） |
| 起始 SOC 标准差 | 0.107 |
| 稳态充电时刻 | **04:45（谷段）+ 12:00（平段）** |
| 稳态日均净收益 | **\$923.62** |

**三个可直接进论文的发现：**

1. **最优起始电量不是满的，是 36.8%。** 每天"充满电再出门"会让司机在早上背着 \$0.28/kWh 的峰值电价成本白白耗掉——最优做法是**带着够用但不多的电出门**，把"必须补的量"留到谷段。
2. **影子价格 $\mu = \$0.2414/kWh$ 落在谷段 \$0.11 与峰段 \$0.42 之间**——它既不等于最便宜电价，也不等于最贵电价，而是**"跨日存着的电"这件事本身的市场价**。这是把 TOU 之外的第三种价格引入决策：司机在盘算"我现在多充的电，明天还能不能按这个价用掉"。
3. **单日模型把"开机满电"当成免费的，系统性偏高 \$22.84（2.4%）。** 单日 MDP 报 \$946.46，循环稳态报 \$923.62。这个差额本身就是一条洞见：**任何忽略跨日状态的电动车调度模型都会高估收益。**

> 输出：`results/cyclic_multiday.csv`、`results/cyclic_day_trace.csv`、`results/ablations_summary.json`
> 代码：`code/src/ablations.py`（`cyclic_value_iteration` / `shadow_price` / `run_cyclic_days`）

### 4.3 模型一致性验证（v2 的前提）

v2 之前，**规划器和仿真器的规则不一致**：DP 在电量不足以覆盖整格时**直接丢弃该概率质量**（legacy），而蒙特卡洛仿真器是"按剩余电量部分服务"。这会让规划器的目标函数 ≠ 实测量。

改成一致（partial service）后：

| 变体 | $V(0, 0.80)$ | MC 实测净收入 | MC 标准误 | 差异 | 差异/标准误 | 可行率 |
|---|---|---|---|---|---|---|
| legacy（丢弃概率质量） | \$939.30 | \$943.58 | ±\$1.85 | \$4.28 | 2.31 SE | 98.5% |
| **consistent（部分服务）** | **\$939.55** | **\$943.69** | ±\$1.84 | **\$4.13** | **2.25 SE** | 94.1% |

两者差异都在 2.3 个标准误内，**规划器与仿真器在统计上一致**——这正是把 DP 值当作"预期收益"来解读的前提。论文里作为**实现正确性检验**报告，不当作主结果。

> 输出：`results/model_consistency.csv`

## 5. 敏感性分析（已完成 ✅，7 组）

单参数扫描，其余固定在基准值。

| # | 参数 | 范围 | MDP 增益（对"按最便宜电价充"） | 判读 |
|---|---|---|---|---|
| S1 | 电池容量 | 25 → 80 kWh | **+\$453.58 → +\$15.97** | **最强驱动因素**；电池越大问题越无趣 |
| S2 | 百公里能耗 | 0.18 → 0.45 kWh/km | **+\$46.21 → +\$532.06** | 耗电越凶越需精细排程 |
| S3 | 充电桩功率 | 7 → 200 kW | +\$263.72 → +\$158.87 | 慢桩增益更高（逼出更多排程决策） |
| S4 | 车队载客率 | 40% → 100% | −\$0.71 → **+\$284.56** | 竞争越激烈、机会成本越高，MDP 越值钱 |
| S5 | 车费水平 | ×0.7 → ×1.5 | **+\$117.89 → +\$255.27** | 车费越高、充电的机会成本越大 |
| S6 | TOU 峰谷价差 | ×0（平价）→ ×2 | **+\$168.46 → +\$170.72** | **反直觉：几乎无影响**（见 §4 A2） |
| S7 | 起始 SOC | 30% → 95% | **+\$497.45 → +\$164.15** | 电量越少越要精打细算 |

> 输出：`results/sensitivity.csv`，图 `figures/F3_sensitivity.png`

### 5.6 S6 的解释（论文必写）

价差变大让"跟着电价走"显得更聪明，但**同时**让"在最贵时段跑车"的损失更大——**两者几乎完全抵消**：增益从 +\$168.46 只变到 +\$170.72（+1.3%）。真正的决定因素是**机会成本（车费 × 载客率），不是电价**。

> **对于要赚钱的充电决策，提高峰谷价差并不能替代优化。** 这解释了为什么网约车补能问题不能照搬纯 EV 错峰充电结论。

### 5.7 时间价值（VOT）校准 —— 独立敏感性 ⭐

这是最硬的一条稳健性检验。

**我们模型的隐含 VOT**：

| | 数值 |
|---|---|
| 04:30 深夜（谷段） | \$7.0/h |
| 18:00 晚高峰 | **\$93.5/h** |
| 全时段均值 | \$53.0/h |

**文献实测值**：

| 来源 | VOT |
|---|---|
| Mehditabrizi, Namadi, Cirillo (2026) *Travel Behav. Soc.* 44:101279 | \$15.20/h |
| Dorsey, Langer, McRae (2022) NBER WP 29831 | **\$27.54/h**（= 当地中位工资 89%） |
| Sunada & Xia (2026) SSRN 6296418 | 平均工资的 27% |

**我们比文献上界高 3.4 倍**，因为用了原始订单到达率 × 毛车费，**未扣空驶、等单、平台抽成**。

**因此把车费按 0.294 缩放**，使峰值 VOT 落到 NBER 实测值，重解 MDP：

| `fare_scale` | 峰值 VOT | 全时段均值 VOT | MDP 充电时刻 | 可行率 |
|---|---|---|---|---|
| 1.000 | \$93.5/h | \$53.0/h | 04:45, 11:15, 20:30 | 96% |
| 0.700 | \$65.4/h | \$37.1/h | 04:45, 11:30, 20:30 | 96% |
| 0.500 | \$46.7/h | \$26.5/h | 04:45, 11:30, 20:30 | 92% |
| 0.400 | \$37.4/h | \$21.2/h | 04:45, 11:30, 20:30 | 90% |
| **0.294** | **\$27.5/h** | **\$15.6/h** | **04:30, 12:30** | **88%** |

**机会成本在真实范围内变动 3.4 倍，主结论纹丝不动**：
1. **深夜谷段那一格在每一档都被选中**（04:45，最低档 04:30）
2. **永远至少有一格落在最便宜电价之外**（11:15 / 20:30 或 12:30，均在平段）

> 诚实补充：车费压到 0.294 后**可行率从 96% 降到 88%** —— 车费低意味着整天可跑的单更少、更难跑完。**主结论（谷段之外还要充）不受影响，但绝对可行性会退化**，论文里要写明。

> 脚本：`code/src/vot_check.py`（计算隐含 VOT）、`code/src/vot_rescale.py`（重标定重解）
